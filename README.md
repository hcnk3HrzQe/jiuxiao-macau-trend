# 澳门 · 九肖中特 连中榜 · 每小时票数快照

追踪第三方论坛「**澳门九肖中特**（tid=31, lotteryType=2）**连中榜**」每一期从开局到开奖的**票数上涨过程**。

- 自动抓取（GitHub Actions 定时任务）：**常规每小时 1 条**；**开奖前加密到每 5 分钟 1 条**（中国时间 **21:02 ~ 21:32**，错开整点与 5 分刻度降延迟）
- 一期一个文件，每次往文件末尾**追加一条**记录
- 到下一期自动切到新文件（**按数据里的期号切，不靠时钟**）

## 数据格式

`data/{期号4位}.json` —— 一个 JSON 数组，每行一条：

```json
[
{"t":"2026-10-18T00:00:04+08:00","period":291,"drawAt":"2026-10-18T21:32:00+08:00","board":400,"n":12,"votes":{"鼠":1,"牛":0,"虎":0,"兔":0,"龙":2,"蛇":0,"马":1,"羊":0,"猴":0,"鸡":3,"狗":0,"猪":0}},
{"t":"2026-10-18T01:00:03+08:00","period":291,"drawAt":"2026-10-18T21:32:00+08:00","board":400,"n":63,"votes":{"鼠":4,"牛":3,"虎":1,"兔":1,"龙":6,"蛇":2,"马":3,"羊":1,"猴":2,"鸡":8,"狗":1,"猪":1}}
]
```

| 字段 | 含义 |
|---|---|
| `t` | 本次抓取时刻（东八区 `+08:00`） |
| `period` | 当期期号（当前未开奖的那期） |
| `drawAt` | 该期开奖时刻（东八区） |
| `board` | 连中榜人数 |
| `n` | 已发帖（已投票）人数，随时间上涨 |
| `votes` | 12 生肖 → 票数；随时间上涨 |

## 怎么用

固定 `period`，把记录按 `t` 排序：

- `n` 的曲线 = **进场节奏**（大家几点开始投）
- `votes[肖]` 的曲线 = **各肖爬升**（谁在下午猛涨）
- 每小时取 `votes` 前 3 = **头部换位**（有没有暗马反超）

示例（Python）：

```python
import json
recs = json.load(open("data/0291.json", encoding="utf-8"))
for r in recs:
    top3 = sorted(r["votes"].items(), key=lambda x: -x[1])[:3]
    print(r["t"], "n=%d" % r["n"], top3)
```

## 数据来源与说明

- 来源：第三方论坛公开接口（只读 GET）：
  - `.../h5/index/apiHost` → 动态域名
  - `.../h5/index/lastLotteryRecord?lotteryType=2` → 当期期号 / 开奖时刻
  - `{host}/forums/h5/prediction/rank?type=1&predictionTypeId=31&lotteryType=2…` → 连中榜名单
  - `{host}/forums/h5/prediction/prediction/detail?userId=…` → 每人选肖明细
- **票数 = 当前连中榜成员对该期的选肖累加**。榜单每期轮换，因此同一旧期的票数会随时间漂移 —— 这正是需要「当期定时快照」的原因。
- 采集脚本 `collect.py` 只用 Python 标准库。

## 已知限制

- GitHub Actions 的 `cron` 可能延迟数分钟，极少数情况跳过一次（缺一条，不影响换期）。
- 第三方接口可能变更（域名轮换 / 字段调整），届时采集会失效并报错。
